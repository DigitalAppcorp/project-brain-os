# Pattern — Minimum Useful Real Core

Use when a module is central to the MVP and a fake door would be misleading.

## Process
1. identify the smallest complete user value loop;
2. make that loop real and persistent;
3. exclude advanced/expensive capabilities;
4. measure real behavior;
5. expose selected advanced capabilities as contextual experiments;
6. prioritize extensions using behavior + intent, not abstract votes.

## Good shape
discover → enter → perform core action → receive value → return

## Avoid
- a product full of “coming soon” cards;
- implementing every advanced feature before evidence;
- presenting fake activity as real;
- creating a separate fake door for every micro-feature.
