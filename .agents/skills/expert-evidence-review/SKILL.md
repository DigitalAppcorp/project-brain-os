# Expert Evidence Review — Brain OS

Apply to **nontrivial** work whenever quality, uncertainty, external evidence, execution or independent review matters. This is a repo-level discovery adapter; the **source of truth** remains [Expert Evidence Protocol](../../../patterns/EXPERT_EVIDENCE_PROTOCOL.md), with [regression fixtures](../../../patterns/EXPERT_EVIDENCE_FIXTURES.md).

Ask: (1) What would a highly competent practitioner do and avoid? (2) What **original** material supports the decision? (3) Which domain-specific workflow fits? (4) Which verifiable evidence could **falsify** success?

Use LIGHT/STANDARD/CRITICAL proportionally. Respect existing Brain OS and specialist authority, independent approvals, privacy and production gates. If untested, mark NOT_TESTED; internal self-review isn't external validation. Don't present skills/docs as model training. More work or longer reports are not intrinsically better.
