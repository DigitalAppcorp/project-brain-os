# FEATURE VALIDATION FRAMEWORK

## Choose the right validation surface

### Optional/new module
Prefer the cheapest honest test:
- fake door;
- one-question intent;
- prototype;
- landing;
- waitlist;
- concierge/manual flow.

### MVP-critical module
If a fake door would make the product feel incomplete or generate low-context evidence:
1. define the minimum useful real cycle;
2. build that core only;
3. measure real behavior;
4. validate advanced capabilities contextually inside it.

## Evidence hierarchy
Stronger signals generally include:
1. real repeated use;
2. contextual intent after use;
3. conversion/action;
4. revisit;
5. abstract click/interest.

## Rules
- measure unique accounts/users when that matches the decision unit;
- repeated clicks do not inflate demand;
- internal interest does not prove external acquisition;
- do not ask users to vote on every micro-feature;
- only surface experiments whose result changes an investment decision.
